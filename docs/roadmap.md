# MangaTranslator 产品路线图

> 状态：规划中  
> 时间策略：当前不承诺发布日期；以版本完成标准和质量门槛推进  
> V0.1 决策基线：[`docs/technical-decisions.md`](technical-decisions.md)  
> V0.2 决策基线：[`docs/v0.2-technical-decisions.md`](v0.2-technical-decisions.md)  
> V0.3 决策基线：[`docs/v0.3-technical-decisions.md`](v0.3-technical-decisions.md)


## 1. 产品愿景

MangaTranslator 是面向漫画翻译与校对的桌面工作台。它将导入、文本区域编辑、OCR、翻译、清除、排版、人工检查和导出组织成可理解、可恢复、可人工干预的工作流。

产品不以“完全无人校对的一键成品”为目标。自动能力必须保留来源、不确定性和人工修改入口；用户修改不得被迟到的后台结果静默覆盖。

## 2. 路线概览

| 版本 | 定位 | 用户获得的核心能力 | 状态 |
| --- | --- | --- | --- |
| V0.1 | 人工辅助翻译闭环 | 不依赖自动检测，完成导入、框选、OCR、翻译、排版和导出 | Planned |
| V0.2 | 自动文本检测 | 自动生成可人工修正的文本区域，并扩展 CBZ/PDF 导入 | Planned |
| V0.3 | 整章智能工作流 | 使用上下文、术语和批处理完成整章翻译与集中校对 | Planned |
| V0.4 | 质量、性能与兼容性 | 提升复杂页面效果、大项目性能、格式覆盖和恢复能力 | Planned |
| V1.0 | 稳定发布 | 形成可长期使用、可升级、可诊断的正式桌面产品 | Planned |

版本号表达能力成熟度，不代表发布日期。若某项能力无法达到质量门槛，可以缩小范围或延期，但不能用不可编辑、不可恢复的结果替代完成标准。

## 3. V0.1：人工辅助翻译闭环

分阶段执行清单见 [`docs/plan/v0.1/README.md`](plan/v0.1/README.md)。

### 版本目标

建立第一个可用的纵向切片。即使没有自动文本检测，用户也能以人工区域编辑为基础完成漫画翻译并导出结果。

### 用户价值

用户可以创建项目、导入图片、手工标记文本区域、获取或输入原文与译文、清除原文字迹、排版译文、保存进度并重新打开继续工作。

### 核心范围

- 创建、打开、保存、另存和恢复目录型项目；默认复制源图并只保存相对路径。
- 导入 JPG/JPEG、PNG、WEBP 和图片文件夹，并保持稳定页面顺序。
- 页面列表、漫画画布、Inspector 和基础命令区。
- 手工创建、选择、移动、缩放和删除矩形 TextRegion。
- 原文、译文和基础排版属性编辑。
- 接入一个经过格式与许可证验证的 Manga OCR ONNX 实现，并保留人工录入入口。
- 接入一个 OpenAI-compatible Chat Completions 适配器，使用非流式结构化响应并按 Region ID 对齐。
- 简单填白或基础清除层，以及非破坏性译文图层。
- 基础横排、竖排、对齐、换行和字号适配。
- Undo/Redo、单页导出和批量 PNG/JPEG 导出。

### 明确不包含

- 自动漫画文本检测。
- CBZ/ZIP、PDF、CBR、CB7 和 Fixed Layout EPUB 导入。
- 复杂背景智能修复。
- Region 旋转、多边形编辑和独立阅读顺序工具。
- 流式 LLM 响应、Provider 专属 SDK 和 WEBP 导出。
- 完整日文禁则、振假名和高级文本塑形。
- 跨页上下文和整章任务调度。
- Translation Memory 和完整术语工作流。
- 精确气泡、分镜或拟声词识别。

### 前置依赖

- C++23、Qt Widgets 6.11 和 FluentQt 工程可以稳定构建。
- 项目文件能够表达页面、Region、文本、排版和非破坏性图层。
- 至少一个 OCR 和一个翻译 Provider 完成可行性验证。

### 完成标准

用户可以稳定走通：

```text
创建或打开项目
→ 导入图片
→ 手工框选文本区域
→ OCR 或人工录入原文
→ 翻译或人工录入译文
→ 清除原文并排版
→ Undo/Redo
→ 保存并重新打开
→ 导出单页或整组图片
```

重新打开项目后，页面顺序、Region、文字、排版和人工修改保持一致；任何失败都不能破坏源图或已有项目内容。

### 主要风险与决策点

- 项目格式过早固化：V0.1 使用 JSON Schema Draft 2020-12，并明确 `projectVersion`、`schemaVersion` 和 `formatVersion`。
- Undo/Redo 边界不清：人工编辑闭环稳定前不扩展复杂自动能力。
- 异步结果覆盖人工修改：无法可靠处理冲突时，不允许自动写入最终结果。
- 基础排版质量不足：优先保证可人工调整，不追求首版完全自动适配。

## 4. V0.2：自动文本检测

### 版本目标

减少逐个手工框选的成本，同时保持检测结果完全可见、可修改、可删除和可重新运行。

### 用户价值

用户导入漫画后可以自动获得文本区域、文字行和 Mask，再对错误结果进行人工修正并继续 OCR、翻译和排版。

### 核心范围

- 固定 1024×1024 输入的 comic-text-detector ONNX 候选模型，使用 ONNX Runtime CPU；再分发许可通过审核后才能随应用发布。
- 页面级自动检测并生成 TextRegion、Lines 和 Mask。
- 检测置信度、运行状态、失败原因和需要检查标记。
- 自动结果的选择、移动、缩放、合并、拆分和删除。
- 人工区域与自动区域来源区分。
- 阅读顺序基础推导和人工调整。
- 具有路径、Entry 类型和资源上限保护的 CBZ/ZIP 导入。
- Qt PDF 300 DPI 导入，并执行 32 MP、8,192 px 和 512 MiB 工作集限制。
- OpenCV Telea 基础 Inpaint；Navier-Stokes 作为显式替代算法。
- 页面级一键执行检测、OCR、翻译、清除和排版。

### 明确不包含

- 无人值守的整章最终输出承诺。
- 跨页翻译上下文。
- 复杂气泡、分镜和拟声词完整语义检测。
- 多设备分布式推理。
- DirectML/CUDA、动态模型输入、多模型切换、嵌套归档和加密归档。
- Region 旋转、多边形编辑和 LaMa。

### 前置依赖

- V0.1 的 Region 编辑、Undo/Redo 和项目持久化稳定。
- 检测模型输入输出与文件 Hash 已验证；权利链、再分发许可和资源分发方式明确。
- 大图缩放、坐标映射和 Mask 对齐经过验证。

### 完成标准

用户导入图片、CBZ 或 PDF 后，可以自动看到与源图对齐的文本区域，修正误检和漏检，并继续完成 OCR、翻译、排版和导出。重新运行检测不会静默覆盖人工区域或人工几何修改。

### 主要风险与决策点

- 模型在不同画风和语言下泛化不足：保留手工创建和局部重跑作为正式路径。
- Mask 或坐标偏移：未通过多分辨率对齐测试前不进入后续版本。
- 模型体积与硬件兼容：必须提供清晰的下载、校验、CPU 状态和缺失模型回退说明。

## 5. V0.3：整章智能工作流

### 版本目标

从“逐页工具”发展为“整章工作台”，提高跨页一致性、批量处理效率和集中人工校对体验。

### 用户价值

用户可以配置整章任务，持续查看每页各阶段进度，暂停、继续、取消和重试失败项；翻译能够使用页面上下文、术语和阅读顺序，并在完成后集中检查问题页面。

### 核心范围

- 使用 `project.db`、SQLite WAL 和页面 × 阶段状态机的整章批量任务，以及暂停、取消、重启恢复、stale 传播和局部重试。
- 保持单页提交和输出，使用最多前 2 页确认文本、受限章节摘要、有效术语和 TM 候选提供上下文；不静默降级。
- 全局术语、项目术语、确定性覆盖、类别、别名组、禁止翻译、CSV 导入和最终有效术语。
- 独立的项目/全局 Translation Memory；人工确认结果才可进入全局 TM，模糊命中只作为候选。
- 规则式自动阅读顺序候选；当前保存的 `orderIndex` 始终权威。
- 基础日文禁则、竖排标点、混排、字体回退、联合适配、项目预设和可解释溢出。
- 固定漫画 LaMa ONNX 候选的 CPU 推理、切块融合、非破坏性清除层和 OpenCV 回退。
- `Info`、`Caution`、`Error`、`Blocking` 问题规则，以及用户确认的集中校对与导出。

### 明确不包含

- 完全无人审阅的发布级自动成品保证。
- 企业级多人实时协作和权限系统。
- 通用图像编辑器级别的自由绘制能力。
- 所有翻译 Provider 和模型的无差别支持。
- DirectML/CUDA、流式翻译、云后台任务、Region 旋转和多边形 Region。
- 完整振假名、任意路径文字、复杂拟声词艺术字和无人校对成品保证。

### 前置依赖

- V0.2 的自动检测结果可稳定人工修正。
- SQLite 固定在不受已知 WAL-reset 缺陷影响的版本，任务状态迁移与 Backup API 通过故障测试。
- 所有长任务具备取消、过期结果隔离、字段级人工优先和故障恢复能力。
- 术语解析结果与实际翻译请求保持一致。
- 批量任务状态能够在离开页面后继续被发现。

### 完成标准

用户可以导入一整章，配置并启动批量流水线，处理失败、blocked、stale 和需要检查项，在编辑器中完成集中校对，保存后批量导出。任务暂停、应用重启和部分失败不会丢失已完成结果，也不会覆盖人工修改；V0.2 项目能够安全迁移且失败可恢复。

### 主要风险与决策点

- 上下文增加成本和延迟：必须允许控制范围并清楚显示影响。
- 多阶段任务恢复复杂：不能可靠恢复时，优先缩小可恢复边界而不是伪造进度。
- 术语冲突：必须提供确定性覆盖和真实来源追踪。
- 智能修复质量不稳定：保留原图、Mask 和可撤销替换。

## 6. V0.4：质量、性能与兼容性

### 版本目标

集中解决前三个版本积累的质量与规模问题，使应用能够处理更复杂的漫画、更大的项目和更多现实文件环境。

### 用户价值

用户在不同硬件、显示缩放、页面尺寸、语言和文件格式下获得更稳定的编辑、恢复和导出体验，并能理解性能降级或资源缺失的原因。

### 核心范围

- 大项目、大页面和大量 Region 的响应速度与内存控制。
- 项目自动恢复、备份、迁移和损坏诊断。
- CBZ、PDF 与主要图片格式的兼容性完善。
- 导出质量、颜色、透明度、字体缺失和长文本边界处理。
- 模型下载、更新、校验、迁移和硬件兼容体验。
- OCR、检测、翻译、清除和排版质量评估基线。
- Light、Dark、高对比度、高 DPI、文本缩放和窄宽度完善。
- 键盘、屏幕阅读器、IME、CJK、RTL 和长文本检查。
- 日志、诊断包和隐私边界完善。

### 明确不包含

- 大规模在线协作平台。
- 移动端或 Web 端完整编辑器。
- 插件市场和不受约束的脚本执行。
- 与专业图像编辑器竞争的完整绘画工具集。

### 前置依赖

- V0.1–V0.3 的功能边界基本稳定。
- 已建立真实漫画样本、性能样本和故障恢复样本。
- 关键模型和 Provider 有可重复的质量评估方法。

### 完成标准

代表性大项目可以长时间编辑、批处理、保存、重启恢复和导出；关键格式与显示环境通过兼容性矩阵；已知失败具备可操作说明、诊断入口和安全回退。

### 主要风险与决策点

- 优化掩盖结构问题：以真实基线和可测指标决定优化优先级。
- 格式范围无限扩大：只承诺进入支持矩阵并通过样本测试的格式。
- 第三方 Provider 快速变化：通过兼容协议和能力检测降低耦合。

## 7. V1.0：稳定发布

### 版本目标

将 MangaTranslator 从开发中工具提升为可以长期保存项目、可靠升级并面向真实用户发布的稳定桌面产品。

### 用户价值

用户可以放心将真实项目交给应用管理，明确知道数据保存位置、模型和网络能力、隐私边界、故障恢复方式以及受支持范围。

### 核心范围

- 稳定安装、升级和卸载流程。
- 正式项目格式版本与向前迁移策略。
- 支持的系统、硬件、文件格式、模型和 Provider 矩阵。
- 首次使用、模型准备、隐私说明和关键工作流引导。
- 崩溃恢复、诊断信息和问题报告流程。
- 完整发布检查、版本说明和已知问题。
- 核心工作流的自动化回归、性能和视觉验收。

### 发布门槛

- V0.1–V0.4 的完成标准持续成立。
- 现有项目升级不会静默丢失页面、Region、文本、排版或人工修改。
- 导入、编辑、保存、重新打开、批处理和导出主线没有阻断级缺陷。
- 长任务可以取消或明确进入正在停止状态，界面始终保持响应。
- 用户内容、密钥和远程发送边界经过安全与隐私检查。
- 支持矩阵内的 Light、Dark、高对比度、高 DPI、键盘和 IME 场景通过验收。

### V1.0 后候选方向

以下内容不承诺进入 V1.0，将根据用户价值和维护成本重新排序：

- 更丰富的气泡、分镜、拟声词和艺术字能力。
- 可选插件或自定义处理流水线。
- 团队术语库、审阅和协作。
- 更多本地模型与硬件后端。
- Translation Memory 增强和质量分析。
- 项目模板与工作流预设。

## 8. 跨版本质量主线

以下要求不是某个版本末尾才补做的功能，而是从首次出现开始持续成立：

### 数据安全

- 永不覆盖源图。
- 项目保存具有版本和故障恢复能力。
- 自动结果与人工修改可区分、可追踪、可恢复。
- 过期后台结果不得写入新的页面或项目。

### 响应与任务

- 推理、网络、导入、导出和排版不阻塞界面。
- 长任务可取消；不能立即停止时明确显示 `正在停止`。
- 页面切换不使后台任务失去可发现性。

### 视觉与无障碍

- 遵循 `docs/ui` 的页面和控件设计合同。
- Light、Dark、高对比度、正常与窄宽度保持可用。
- 键盘、IME、屏幕阅读器、文本缩放和长文本持续验证。

### 隐私与可诊断性

- 默认不在日志记录完整漫画内容、译文或密钥。
- 远程发送的内容、Provider 和作用范围对用户可见。
- 错误提供安全摘要、影响范围和下一步操作。

## 9. 路线图维护规则

- 新能力先确定目标版本、用户价值和完成标准，再拆 Milestone。
- 单个版本不能因为新增功能而破坏已经成立的端到端主线。
- 范围变化应同步更新本路线图、`docs/feature-design.md` 和相关 UI 设计文档。
- 版本进入开发后，详细 TODO 放入该版本的 Milestone 文件，不继续膨胀本文件。
- 状态使用 `Planned`、`In progress`、`Completed` 或 `Deferred`。
- 没有可靠依据时不填写精确发布日期或完成百分比。
