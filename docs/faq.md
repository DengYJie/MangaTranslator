# 常见问题与排错指南 (User FAQ)

### Q1: 如何下载与配置本地检测 / OCR / 文字消除模型？
- 应用支持通过 ONNX Runtime 运行的漫画版面检测（Koharu RF-DETR 分割模型）、文字识别（Baberu / PaddleOCR-VL-1.6 ONNX）与文字消除（LaMa 漫画修复模型）；
- 三类模型分别放在 `models/detection/<model-name>/1.0.0/`、`models/ocr/<model-name>/1.0.0/` 与 `models/inpaint/<model-name>/1.0.0/` 目录下，每个目录都要带自己的 `manifest.json`；
- 目录可在「设置 -> 模型配置」里改，改完该页会显示每个模型是"有效"还是"校验失败"以及模型 id 与版本；
- 如网络下载 HuggingFace 模型较慢，可使用 `https://hf-mirror.com` 镜像端点加速下载。

### Q2: 如何配置 AI 翻译服务？
- 进入「设置」->「AI 翻译」页面；
- 选择 API 供应商（如 OpenAI、DeepSeek、自定义兼容接口等）；
- 填写 API Key、Endpoint 接口地址及模型名称（如 `gpt-4o-mini`, `deepseek-chat`）；
- 保存后直接发起一次翻译。设置页没有「测试连接」按钮，请求失败会显示在底部状态任务条上并写进日志。
- 端点填 `http://127.0.0.1:11434/v1` 这类本地服务要用 `http`，写成 `https` 会在 TLS 握手阶段就失败；推理模型（例如带思维链的 DeepSeek）单页请求可能跑到一两分钟，超时秒数在同一页可调。

### Q3: 软件意外崩溃后，如何恢复未保存的项目数据？
- MangaTranslator 在每次保存时均会自动维护事务性的 `.bak` 备份文件；
- 重新打开该项目时，如果 `project.json` 校验失败，系统会自动读回最后一次完整保存的备份并提示已恢复，无需您手动确认。

### Q4: 批量处理为什么没有出现单独的页面？
- MangaTranslator 将整章批量工作流整合在编辑器的顶部标题栏菜单中（「处理」->「处理项目」）；
- 在处理过程中，您可以在底部任务条观察进度并「取消任务」，无需在独立页面间跳转。

### Q5: 为什么在设置界面标题栏有一个返回按钮？
- 当您从编辑器或主页进入「设置」时，标题栏左侧会自动呈现返回箭头，点击即可直接返回先前的编辑界面或主页。

### Q6: 运行日志记在哪里？
- 按天写入 `%APPDATA%\logs\manga_YYYYMMDD.log`（Windows 下），同一行同时输出到标准错误；
- 检测、OCR、翻译每次请求的端点、模型名、耗时与错误码都在这里，翻译失败或整页识别为空时先来这里找那一行的错误码。
