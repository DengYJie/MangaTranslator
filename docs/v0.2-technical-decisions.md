# MangaTranslator V0.2 技术决策

> 状态：技术基线；文字检测模型的再分发许可仍是发布门槛
> 核对日期：2026-08-30
> 适用版本：V0.2
> 上游基线：C++23、Qt Widgets 6.11、ONNX Runtime CPU、libarchive、Qt PDF、OpenCV

## 1. 版本目标

V0.2 在 V0.1 人工编辑闭环上增加自动文字检测、CBZ/ZIP 与 PDF 导入、基础 Inpaint、人工阅读顺序调整和页面级流水线。

```text
图片、CBZ/ZIP 或 PDF
→ 自动检测候选 Region、文字行和 Mask
├→ OCR → 翻译 → 排版
└→ OpenCV 基础清除
→ 人工检查并采用
→ 保存与导出
```

自动结果始终是候选。未经用户明确采用，不得覆盖项目中的人工几何、Mask、文字、译文、阅读顺序或排版。

### 1.1 Koharu 参考边界

V0.2 参考 [Koharu](https://github.com/koharu-rs/koharu) 在 2026-08-30 公开文档中的以下设计：

- 使用固定、具名的检测、OCR、翻译和 Inpaint 工作流，而不是让用户拼装任意运行时图。
- 检测同时为 OCR 分支和 Inpaint 分支提供输入；Inpaint 不依赖 OCR 或翻译。
- 阶段无适用输入时明确跳过；后续失败不抹去已完成的候选结果。
- 停止请求后不再启动新阶段；不可中断的原生推理在安全边界返回，未发布结果必须丢弃。
- 分析 Region、语义文本和可见呈现层保持分离。
- 每个处理器独立持有配置，模型惰性加载并复用。

这些内容是产品和调度语义参考，不引入 Koharu 的 Rust、Tauri、WebGPU 或模型运行时依赖。Koharu 的当前模型清单也不是 V0.2 的默认模型清单。

### 1.2 当前 Koharu 模型架构的采用方式

当前 Koharu 使用统一的 Koharu Layout RF-DETR Seg 2XL 产生 text、onomatopoeia、bubble、panel 和实例 Mask，再为 OCR、Inpaint 和翻译分别选择独立模型。较早的 `comic-text-bubble-detector + comic-text-detector-seg + YuzuMarker.FontDetection` 组合不是 V0.2 的参考基线。

MangaTranslator 借鉴“每个处理阶段独立 Profile”和“统一布局检测输出能力”，但不复制 Koharu 的完整模型目录：

- V0.2 的 `ITextDetector` 最低能力仍是 TextRegion、Lines 和 Mask；Bubble/Panel 是可选分析候选，不是 OCR 或人工编辑的前置条件。
- V0.2 每个阶段只有一个生产 Profile，不提供模型选择器或自动模型下载市场。
- Baberu OCR 和 OpenAI-compatible 翻译继续复用 V0.1；OpenCV Telea/NS 是 V0.2 的清除基线。
- PaddleOCR-VL、Manga OCR、Hayai OCR、LaMa/AOT/FLUX/RORem、本地 GGUF 模型和 Provider 专属 Adapter 按路线图后移。

## 2. 文字检测模型

### 2.1 固定候选发布物

V0.2 候选为 [`mayocream/comic-text-detector-onnx`](https://huggingface.co/mayocream/comic-text-detector-onnx)：

| 字段 | 锁定值 |
| --- | --- |
| Model ID | `mayocream/comic-text-detector-onnx` |
| Repository revision | `a5d67ec772adef819ef5b0e7aa701fcf4c8bf74a` |
| File | `comic-text-detector.onnx` |
| File size | 94,669,756 bytes |
| SHA-256 | `1a86ace74961413cbd650002e7bb4dcec4980ffa21b2f19b86933372071d718f` |
| Runtime | ONNX Runtime CPU Execution Provider |
| Input | `images`, float32, `[1, 3, 1024, 1024]` |
| Output | `blk`, float32, `[1, 64512, 7]` |
| Output | `seg`, float32, `[1, 1, 1024, 1024]` |
| Output | `det`, float32, `[1, 2, 1024, 1024]` |

这些张量信息由固定文件通过 ONNX Runtime 实测获得。V0.2 不使用 640×640；不支持动态输入、多模型切换或 GPU Execution Provider。

### 2.2 预处理与后处理

- 原图保持纵横比缩放并 letterbox 到 1024×1024，保存缩放比例和 padding。
- 输入为 NCHW float32，数值缩放到 `[0, 1]`。
- 参考代码意图使用 RGB，但其 OpenCV/PyTorch 路径包含通道转换差异；正式适配器必须用固定样本与参考实现做逐阶段一致性测试后锁定通道顺序，不能只根据注释推断。
- `blk` 作为文本块检测原始输出，`seg` 作为文本 Mask 输出，`det` 作为文字行概率输出；阈值、NMS、DBNet 后处理和 Region 分组属于模型适配器版本的一部分。
- 框、文字行和 Mask 必须去除 padding 并映射回源图像像素坐标。
- 模型 Manifest 同时记录适配器版本和后处理配置；只锁定 ONNX 文件不足以复现最终 Region。

原项目推理代码默认输入尺寸为 1024，并执行 letterbox 与 `/255` 归一化；参见 [`dmMaze/comic-text-detector` 的 inference.py](https://github.com/dmMaze/comic-text-detector/blob/master/inference.py)。

### 2.3 许可证门槛

Hugging Face 仓库元数据将 ONNX 发布物标为 Apache-2.0，但仓库当前只包含 README 与 ONNX 文件，没有独立 LICENSE、转换说明或足以消除派生权利疑问的许可证材料。其指向的原始 [`dmMaze/comic-text-detector`](https://github.com/dmMaze/comic-text-detector) 使用 GPL-3.0。

因此：

- 该 ONNX 文件是技术候选，不是已经批准随应用再分发的依赖。
- 发布前必须确认模型权重授权链、转换者的再许可权限、所需署名以及源代码提供义务。
- 未完成确认时，模型不得进入 Git 或默认发布包；应用只提供 Manifest 驱动的用户侧模型安装入口。
- 若许可无法确认，保持 `ITextDetector` 不变并更换具有明确授权的模型，不改变 V0.2 Domain、UseCase 或 UI 合同。

```json
  "downloadUrl": "https://huggingface.co/mayocream/comic-text-detector-onnx/resolve/a5d67ec772adef819ef5b0e7aa701fcf4c8bf74a/comic-text-detector.onnx",

```

`licenseStatus` 只有在授权链审核完成后才能改为可分发状态。

### 2.5 `ITextDetector` 能力合同

`ITextDetector` 返回统一 `DetectionResponse`，不为每个第三方模型创建新的 Port：

```text
DetectionResponse
├── capabilities
├── textRegionCandidates       required
├── lineCandidates             required
├── maskCandidates             required
├── bubbleCandidates           optional
├── panelCandidates            optional
└── classCandidates            optional
```

- V0.2 只有 TextRegion、Lines 和 Mask 可以进入采用与持久化流程。
- Bubble/Panel/Class 候选可以用于分析 overlay、质量诊断和未来关联，但 V0.2 不持久化为独立 Domain 实体，不参与导出。
- Adapter 必须通过 capability set 区分“模型没有该输出”和“该页没有检测到结果”。
- OCR 只依赖 TextRegion；没有 Bubble/Panel 能力时不得降级为错误。
- 如果以后切换到统一布局模型，Application、Pipeline 和 UI 状态机不改变，只增加可选候选的消费入口。

### 2.6 Koharu Layout RF-DETR 评估边界

Koharu Layout RF-DETR Seg 2XL 是统一布局检测参考候选，不是 V0.2 默认发布物。它在 1152×1152 下输出 text、onomatopoeia、bubble 和 panel 的框与实例 Mask，但不输出 OCR、阅读顺序或文本到气泡的一对一关系。

评估必须记录：

- 与当前 1024 ONNX 候选在同一授权页面集上的 TextRegion/Mask 质量。
- CPU 延迟、峰值内存、模型加载时间和是否存在可验证的 ONNX Runtime CPU 导出。
- SafeTensors/RF-DETR 运行时引入成本，以及模型卡的 custom license、Manga109 学术使用条款和 CUDA 建议。
- Bubble/Panel 输出是否只停留在分析候选，避免模型能力反向扩大 V0.2 产品范围。

没有明确授权和 CPU 部署结论前，不得替换默认 Manifest、进入自动下载或随包分发。

## 3. Mask 格式

### 3.1 持久格式

- 每个 Region 使用局部 Gray8 二值 PNG，而不是整页 Mask。资产矩形可包含扩张所需的页内边距，不必严格等于 Region 几何边界。
- 持久像素只允许 0 和 255：0 表示保留，255 表示清除。
- Mask 的 `originX`、`originY`、`width` 和 `height` 使用源图像像素坐标。
- 自动生成版本与当前有效版本使用两个独立资产引用，避免一个 `asset` 字段同时承担两种语义。

```json
{
  "mask": {
    "format": "png-gray8-binary-v1",
    "originX": 120,
    "originY": 300,
    "width": 420,
    "height": 180,
    "automaticAsset": "assets/derived/masks/{regionId}.automatic.png",
    "effectiveAsset": "assets/derived/masks/{regionId}.effective.png",
    "hasManualOverride": false,
    "generation": {
      "modelId": "mayocream/comic-text-detector-onnx",
      "modelVersion": "a5d67ec772adef819ef5b0e7aa701fcf4c8bf74a",
      "adapterVersion": 1,
      "dilationRadius": 2
    }
  }
}
```

### 3.2 编辑规则

- 初次采用检测结果时，`automaticAsset` 与 `effectiveAsset` 内容相同。
- 用户添加或擦除 Mask 只修改 `effectiveAsset`，并设置 Mask 级人工覆盖。
- 重新生成 Mask 只替换自动版本；人工有效版本必须由用户明确选择后才能替换。
- Mask 合并使用像素 OR；拆分按新 Region 几何裁剪。
- 默认扩张半径为 2 源图像像素，并记录在生成配置中，避免重复扩张。
- 超出页面的部分裁剪。资产缺失、解码失败、尺寸或边界不匹配时进入明确失败状态，不猜测缩放或静默修复。
- 软边缘或灰度权重不属于 `png-gray8-binary-v1`；以后需要时必须增加新的格式版本。

## 4. CBZ/ZIP 导入

### 4.1 产品安全上限

以下是 MangaTranslator 的产品策略，不是 libarchive 默认限制：

| 项目 | V0.2 上限 |
| --- | ---: |
| Entry 数 | 10,000 |
| 单 Entry 解压后大小 | 256 MiB |
| 累计解压后大小 | 2 GiB |
| 压缩比 | 100:1 |
| 目录深度 | 32 |
| 嵌套归档 | 禁止 |
| 符号链接、硬链接及其他特殊文件 | 禁止 |
| 绝对路径、驱动器路径、UNC 路径和 `..` | 拒绝 |
| 非图片普通文件 | 跳过并汇总报告，不写入项目 |

解压数据必须以流式计数执行硬上限；不能只相信 ZIP Header 中声明的大小。压缩大小为 0、未知或无法可靠计算比率时，仍执行单文件与累计绝对上限，并将异常条目标记为不可信。

### 4.2 路径与类型检查

1. 严格解码 Entry 名称；无法可靠解码时拒绝该 Entry 并报告。
2. 将 `\` 与 `/` 按归档路径分隔符处理，再做 Unicode NFKC。
3. 规范化后拒绝空名称、绝对路径、盘符、UNC、`.`、`..`、空路径段和超过 32 层的路径。
4. 解析目标路径，并确认其仍位于本次导入的隔离暂存目录内。
5. 只接受经过图片解码验证的普通文件；不能仅依赖扩展名。
6. 拒绝 symlink、hardlink、设备、FIFO 和其他特殊 Entry。

若使用 libarchive 的磁盘提取 API，同时启用：

- `ARCHIVE_EXTRACT_SECURE_NODOTDOT`
- `ARCHIVE_EXTRACT_SECURE_NOABSOLUTEPATHS`
- `ARCHIVE_EXTRACT_SECURE_SYMLINKS`
- `ARCHIVE_EXTRACT_NO_OVERWRITE`

这些标志在 libarchive 中是可选行为，不是默认保护；参见官方 [`archive.h`](https://github.com/libarchive/libarchive/blob/master/libarchive/archive.h)。应用层检查仍是强制要求。

### 4.3 排序

排序键依次为：

1. UTF-8 解码后的路径；
2. Unicode NFKC 规范化结果；
3. 规范化文本中的自然数字段；
4. 其余文本按 Unicode code point；
5. 规范化路径；
6. 原始路径字节，作为最终稳定 tie-breaker。

比较相等的页面也必须产生稳定顺序。嵌套 CBZ/ZIP、CBR 和 CB7 不进入 V0.2。

## 5. PDF 导入

### 5.1 Qt PDF 语义

使用 Qt 6.11 `QPdfDocument`。`pagePointSize()` 返回 1/72 英寸的 point 尺寸，`render()` 接收目标像素 `QSize`，不是 DPI。目标尺寸按以下关系计算：

```text
targetPixels = pagePointSize / 72 × requestedDpi
```

计算后必须保持原页面纵横比；Qt 文档说明，传入不匹配的纵横比时页面会缩放以覆盖整个目标图像。渲染错误返回空图像。参见 [`QPdfDocument`](https://doc.qt.io/qt-6/qpdfdocument.html)。

### 5.2 V0.2 产品上限

| 项目 | 规则 |
| --- | --- |
| 默认请求 DPI | 300 |
| 单页最大像素总数 | 32 MP |
| 单边最大尺寸 | 8,192 px |
| 单页处理工作集预算 | 512 MiB |
| 工作颜色 | sRGB 8-bit |
| 页面透明度 | 合成到白色背景，不保留 PDF 透明层 |
| 超限页面 | 等比降低实际 DPI并显示警告；仍无法满足预算则该页失败 |
| 页面失败 | 记录具体页码，其他页面继续导入 |

32 MP、8,192 px 和 512 MiB 是应用自身的防护值，不是 Qt 保证。内存预算包含渲染图像、颜色转换和导入复制所需的同时存活缓冲区，不能只按最终 RGBA 字节数计算。

## 6. OpenCV Inpaint

### 6.1 默认配置

```json
{
  "inpaint": {
    "algorithm": "telea",
    "radius": 3.0,
    "maskDilation": 2,
    "version": 1
  }
}
```

- 默认算法为 Telea，默认半径为 3 源图像像素。
- Navier-Stokes 是可选择的替代算法，不作为质量不可判定时的静默自动回退。
- Mask 为空时跳过并报告；Mask 无效时拒绝运行；执行失败时保留原图并将 Region 标记为清除失败。
- 清除层独立保存，绝不修改原始资产。

OpenCV `cv::inpaint` 要求 Mask 为 8-bit 单通道，非零像素表示需要修复；算法标志为 `INPAINT_TELEA` 或 `INPAINT_NS`。其彩色输入支持 8-bit 三通道，但不直接接受 MangaTranslator 的 RGBA 四通道工作图。因此调用前提取 RGB/BGR 颜色平面，生成结果后复制原工作图 Alpha，重新组成 straight-alpha RGBA 清除层；V0.2 的 Inpaint 不改变透明度。Mask 与非不透明像素相交时显示质量警告，不得直接把 RGBA 交给 OpenCV。参见 [OpenCV Inpainting](https://docs.opencv.org/4.x/d7/d8b/group__photo__inpaint.html)。

## 7. 检测结果合并

### 7.1 来源与人工覆盖

Region 来源为：

- `manual`：用户创建。
- `automatic`：模型候选或采用后的自动结果。
- `adopted`：用户明确采用，并保留对应检测运行和模型来源。

不能只使用一个 Region 级 `hasManualOverride` 决定全部覆盖行为。至少分别跟踪：

- geometry override；
- mask override；
- source text override；
- translation override；
- reading order override；
- layout override。

删除自动 Region 形成页面级 tombstone；重跑检测不得自动复活同一候选。合并或拆分生成新 Region ID，同时保留来源 Region ID 关联。

### 7.2 重跑流程

```text
运行检测
→ 生成不可变候选集
→ 与当前页面 Region 确定性匹配
→ 显示新增、更新、保留和 stale 差异
→ 用户确认
→ 以一个复合命令采用
```

匹配只在同一页面进行：

- IoU ≥ 0.5：作为高置信候选匹配。
- IoU 0.3–0.5：结合中心距离和 Mask 重叠，仅形成需要检查的匹配建议。
- 一个旧 Region 最多匹配一个新 Region；使用稳定排序和确定性一对一分配。
- 匹配阈值是 V0.2 初始产品参数，必须用代表性样本评估，不是模型或行业标准。

采用规则：

| 情况 | 行为 |
| --- | --- |
| 未修改自动 Region 与新结果匹配 | 用户采用后更新允许更新的模型字段；保留原 Region ID |
| 自动 Region 未匹配 | 标记 `stale`，默认保留 |
| 新检测结果未匹配 | 用户采用后生成新 UUID |
| Manual Region | 始终保留，不参与自动覆盖 |
| 自动 Region 的人工几何 | 保留几何；新几何只作为候选 |
| 人工 Mask、文字、译文、顺序或排版 | 对应字段永不被检测结果覆盖 |
| 已删除自动 Region | 保留 tombstone，不自动复活 |
| 合并或拆分 | 新建 Region，并保留历史关联 |

检测任务完成本身不进入 Undo 栈。用户采用候选时，全部变化作为一个可撤销复合命令进入 Undo/Redo。

## 8. 页面级流水线

V0.2 增加以下 UseCase 能力：

- `DetectTextUseCase`
- `ImportArchiveUseCase`
- `ImportPdfUseCase`
- `InpaintPageUseCase`
- `AdjustReadingOrderUseCase`
- `RunPagePipelineUseCase`

流水线使用固定 DAG：

```text
检测 ─→ OCR ─→ 翻译 ─→ 排版 ─┐
  └────→ 清除 ───────────────┼→ 预览与采用
原图 ────────────────────────┘
```

- V0.2 只提供“当前页”和“选中 Region”范围。检测只能按当前页运行；OCR、翻译、清除和排版可按选中 Region 缩小范围。
- “选中页”和“整个项目”范围属于 V0.3 批量任务，不在 V0.2 以隐藏循环实现。
- 用户可以选择任意非空阶段子集；系统不静默补齐未选择的前置阶段。常用预设明确展开为固定阶段集合。
- 同一项目会话最多有一个页面流水线 invocation；普通缩略图和页面加载不占用该执行槽。

每一阶段独立记录 `pending`、`running`、`succeeded`、`skipped`、`blocked`、`failed`、`cancelled` 或 `stale`，并携带：

- Page ID 与输入 Region ID 集合；
- 请求 generation；
- 不可变输入快照；
- 模型、适配器和处理配置版本；
- 阶段进度；
- 可恢复错误；
- 局部重试边界。

`succeeded` 只表示生成了可审阅候选，不表示候选已写入 Domain；采用状态单独记录。每个成功阶段把不可变 candidate patch 发布到本次 invocation 的暂存工作区，后续阶段可以读取该 patch，而不需要先覆盖当前项目。

阶段失败不得把整页标记为成功。依赖失败结果的阶段标记 `blocked`；无适用输入标记 `skipped`；输入 revision 或 generation 已变化标记 `stale`。用户可修正输入后从失败阶段重试。取消和过期 generation 的结果不得发布到候选工作区或写入当前页面。

停止请求后不再调度新阶段。正在执行且无法中断的原生调用允许在安全边界返回；若停止发生在 candidate patch 发布前，其结果必须丢弃。较早阶段已经发布的候选仍可审阅。

用户点击采用时，UseCase 再次检查项目 revision、字段级人工覆盖和候选来源。一次“采用所选结果”产生一个复合 Undo 命令；只切换已经原子写入的派生资产引用，Undo/Redo 不执行模型推理或文件 I/O。重跑只替换未采用的候选，不直接替换人工或已采用内容。

### 8.1 V0.2 模型基线与 Koharu 对照

| 阶段 | V0.2 基线 | Koharu 当前模型目录 | V0.2 决策 |
| --- | --- | --- | --- |
| 检测 | `comic-text-detector.onnx` 技术候选，ONNX Runtime CPU | Koharu Layout RF-DETR Seg 2XL | 保持现候选和可替换 `ITextDetector`；两者都必须先过授权门，不引入 RF-DETR/SafeTensors/CUDA-oriented 栈 |
| OCR | 复用 V0.1 Baberu OCR Adapter | PaddleOCR-VL 1.6、Manga OCR、Baberu OCR、Hayai OCR | V0.2 不增加 OCR 模型选择器 |
| 翻译 | 复用 V0.1 OpenAI-compatible Adapter | LFM/Ministral/Gemma/Qwen GGUF、本地/云 Provider、机器翻译 Provider | V0.2 不增加 llama.cpp、本地模型下载、uncensored 分类或 Provider 专属 Adapter |
| 清除 | OpenCV Telea 默认，Navier-Stokes 显式可选 | LaMa/AOT 直接修复，FLUX.2/RORem 生成式修复 | 保持确定性 CPU 基线；LaMa 仍属于 V0.3 |
| 排版 | 复用共享 `manga_rendering` | 共享场景与渲染路径 | 保持 UI 预览和导出同源 |

Koharu Layout RF-DETR Seg 2XL 能输出 text、onomatopoeia、bubble 和 panel 的框与实例 Mask，但不输出 OCR 或阅读顺序。其模型卡要求用户遵守 Manga109 的学术使用条款，且明确建议 CUDA。它只能作为质量比较样本，不能在 V0.2 中默认下载、随包分发或替换既定 CPU 运行时。

### 8.2 每阶段 Model Profile

检测、OCR、翻译和 Inpaint 分别持有一个类型化 Profile：

```text
ModelProfile
├── profileId
├── processorKind
├── modelId + modelVersion
├── adapterVersion + configVersion
├── runtime + backend
├── capabilities
├── manifestIdentity
├── licenseStatus
└── nonSensitiveParameterSummary
```

- V0.2 的 Profile 是配置隔离和可追踪身份，不等于多模型选择功能。
- 同一处理器的设置不能泄漏到另一处理器；错误、进度和候选来源携带对应 Profile identity。
- API Key、Prompt 全文、模型访问 token 和本机绝对路径不进入 Profile、项目文件或日志。
- Profile 变化使依赖旧 Profile 的未采用候选 stale；已经采用的结果保留来源，不自动重跑。
- 排版使用确定性 `manga_rendering` 配置快照，不作为可下载 ML Model Profile。

## 9. V0.2 测试门槛

- 固定 ONNX 文件的 Hash、输入输出元数据和参考样本结果。
- 预处理 letterbox、padding 去除、框/行/Mask 源坐标回映。
- Mask 的自动/有效版本、扩张、编辑、合并、拆分和损坏恢复。
- ZIP Slip、绝对路径、盘符、UNC、symlink、hardlink、特殊文件、伪装扩展名和压缩炸弹。
- Unicode NFKC 与自然排序的稳定性。
- PDF 纵横比、DPI 换算、32 MP/8,192 px/512 MiB 限制和单页失败继续。
- RGBA 与 OpenCV 三通道转换、Mask 校验和清除层非破坏性。
- 检测重跑的一对一匹配、tombstone、字段级人工覆盖和复合 Undo/Redo。
- 各流水线阶段的成功、失败、取消、过期结果和局部重试。
- 固定 DAG 的分支调度、显式跳过/阻塞、停止安全边界、候选暂存和采用前 revision 复核。
- 一次候选采用对应一个复合 Undo 命令，Undo/Redo 不触发推理或 I/O。
- `ITextDetector` required/optional capability、空结果与不支持能力的区分，以及 Bubble/Panel 不进入 V0.2 Domain/导出。
- 每阶段 Profile 的配置隔离、候选来源、Profile 变化后的 stale 传播和敏感字段排除。

## 10. 明确不包含

- DirectML、CUDA 或其他 GPU 后端。
- 动态模型输入、多检测模型选择或在线模型切换。
- 独立 Bubble/Panel Domain 编辑器、气泡到文本的完整语义关联和分镜驱动阅读顺序。
- LaMa 或生成式复杂背景修复。
- CBR、CB7、嵌套归档和加密归档。
- Region 旋转和多边形编辑。
- 跨页上下文、完整术语工作流和无人值守整章调度。
