# 视觉与交互基础

## 1. 设计坐标和密度

文档中的尺寸使用逻辑像素。界面在不同 DPI 和缩放比例下应保持一致的逻辑尺寸与信息层级，不得按截图物理像素固定布局。

所有主要尺寸、边距和位置遵循 4 px 网格：

| 用途 | 基准值 |
| --- | --- |
| 微间距 | 4 px |
| 紧密控件间距 | 8 px |
| 表单行内部间距 | 12 px |
| 页面常规间距 | 16 px |
| 分组间距 | 24 px |
| 页面边距 | 24–36 px，随窗口宽度响应 |
| 紧凑按钮高度 | 28–32 px |
| 常规按钮/输入高度 | 32–36 px |
| 列表行高度 | 40–64 px，依信息密度决定 |
| 桌面点击目标 | 不小于 32×32 px |

页面不通过堆叠边框制造层级。优先顺序是：间距、标题层级、背景 Surface、细描边、最后才是阴影。

## 2. 窗口层级与材料

### 2.1 Base layer

- 整个长生命周期窗口参考 Mica 作为基础层。
- 系统 Mica 不可用时，使用主题感知的不透明 Surface 回退，不模拟高成本实时模糊。
- 标题栏和主导航应与窗口基础层自然融合，不做独立高饱和色块。

### 2.2 Content layer

- 页面内容使用比 Base layer 更明确的中性 Surface。
- 页面列表、Inspector 和设置导航属于二级长期 Surface，使用轻微色差或 1 px 分隔线，不使用 Acrylic。
- 漫画画布保持中性深灰工作区，即使应用为浅色主题也不变成纯白，以维持页面边缘可见性；画布工具和文字仍响应主题。

### 2.3 Transient layer

- `Flyout`、`MenuFlyout` 和轻量上下文面板参考 Acrylic。
- `ContentDialog` 后方使用 Smoke 遮罩，阻止底层交互。
- 材料不可用、节能模式或高对比度模式下必须回退到不透明颜色。

官方参考：[Windows 应用中的材料](https://learn.microsoft.com/zh-cn/windows/apps/develop/ui/materials)。

## 3. 颜色语义

禁止在页面中直接指定品牌色或状态色。所有页面使用统一的 Fluent 语义主题与颜色 Token，不建立平行的应用主题层。

下表描述需要覆盖的语义用途，不是 MangaTranslator 要新增的 Token 名。设计稿应使用现有的 Fluent 语义颜色，不另建别名体系。

| 语义用途 | 使用位置 |
| --- | --- |
| 窗口基础背景 | 窗口基础层 |
| 分层背景 | 导航、Inspector、页面面板 |
| 卡片背景 | 内容分组、设置组、任务摘要 |
| 画布背景 | 漫画工作区 |
| 主要前景 | 标题、重要数值 |
| 次要前景 | 正文、标签 |
| 弱化前景 | 元数据、占位和次要说明 |
| Surface 描边 | 长期 Surface 边界 |
| 控件描边 | 输入与普通按钮边界 |
| 强调色 | 主操作、选中指示器、活动进度 |
| 成功状态 | 保存成功、阶段完成 |
| 警告状态 | 低置信度、需要检查 |
| 严重错误状态 | 失败、破坏性动作 |
| 信息状态 | 普通信息和提示 |
| 焦点描边 | 双层键盘焦点框 |

正文文字与背景对比度至少 4.5:1；大字和非文本关键边界至少 3:1。高对比度模式必须遵循系统语义颜色，不得强制保留品牌色。

控件专属的间距、尺寸、圆角和动画时长以对应控件文档为准。跨页面共享的视觉值应保持一致，自定义控件也必须使用同一套 Fluent 语义颜色。

## 4. 形状与边界

| 元素 | 圆角 |
| --- | --- |
| 小型内部元素、选中指示器 | 2–4 px |
| 输入框、按钮、列表选中背板 | 4–6 px |
| 内容卡片、设置组、Flyout | 8 px |
| 大型空状态、导入 Drop Zone | 8–12 px |
| Badge、状态点 | 圆形 |

相邻嵌套 Surface 的外圆角应大于内圆角。圆角不得导致列表行之间出现不必要的“药丸堆叠”。

## 5. 字体和层级

字体优先使用系统 UI 字体；中文回退为 Microsoft YaHei UI 或系统默认中文 UI 字体。漫画排版字体不影响应用 UI 字体。

| 角色 | 建议字号 | 用途 |
| --- | --- | --- |
| Caption | 12 px | 元数据、状态栏、快捷键信息 |
| Body | 14 px | 常规正文、表单内容 |
| Body Strong | 14 px Semibold | 行标题、卡片标题 |
| Subtitle | 16–18 px Semibold | 区块标题 |
| Title | 24–28 px Semibold | 页面标题 |

- 页面标题使用 Sentence case，不全大写。
- Eyebrow 仅作辅助分类，不承担主要语义；中文界面可省略英文 Eyebrow。
- 可截断的文本必须提供完整内容的 `ToolTip`；禁止让关键状态只能通过被截断文字表达。
- 用户文本、文件名和模型名必须支持长文本、CJK、RTL 和 Emoji。

## 6. 动效系统

动效服务于状态连续性，不装饰等待时间。

| 动效 | 时长 | 曲线 | 使用位置 |
| --- | --- | --- | --- |
| Hover/Pressed 颜色过渡 | 80–120 ms | ease-out | 按钮、列表行、区域框 |
| 选中指示器移动 | 160–220 ms | 标准曲线 | 导航、SelectorBar、缩略图 |
| Expander 展开/收起 | 180–240 ms | 标准曲线 | Inspector、设置子项 |
| Pane 显示/隐藏 | 200–280 ms | decelerate / accelerate | 页面列表、Inspector、导航 Surface |
| 页面内容进入 | 180–240 ms | decelerate | 一级导航后内容替换 |
| Flyout | 120–180 ms | 标准曲线 | 下拉、上下文命令 |
| 任务完成强调 | 240–360 ms | ease-out | 状态图标、进度完成 |

标准曲线可参考 `cubic-bezier(0.33, 0, 0.67, 1)`。界面必须尊重系统“减少动画”设置：停用平移、缩放和连续动画，只保留即时或短淡入淡出状态变化。

不要对以下内容做动画：

- 用户拖动中的 Region 与选择柄；它们必须 1:1 跟随指针。
- OCR/翻译文本本身的逐字出现；这会妨碍校对。
- 高速更新的进度数字；最多以 100 ms 节流刷新。
- 因窗口缩放触发的每个中间布局值；布局应稳定重排。

## 7. 响应式断点

官方通用断点为 Small `<640`、Medium `641–1007`、Large `>=1008` 有效像素。本项目是密集桌面编辑器，在此基础上增加工作台断点：

| 宽度 | 模式 | 应用行为 |
| --- | --- | --- |
| `>=1440` | Wide workbench | 编辑器三栏常驻；页面内容采用舒适边距 |
| `1200–1439` | Standard workbench | 三栏常驻，缩小左右栏和页面边距 |
| `1008–1199` | Compact workbench | 页面列表缩为紧凑栏；Inspector 保留或按用户偏好折叠 |
| `720–1007` | Narrow | 主导航为 Overlay；页面列表默认隐藏；Inspector 作为 Overlay Pane |
| `<720` | Minimum recovery | 不保证完整编辑效率；只保留画布、核心命令和可逐个打开的辅助面板 |

高度断点：

- 高度 `<720`：隐藏非关键说明，缩小页面上下边距，设置页必须滚动。
- 高度 `<560`：CommandBar 保留单行并增加 Overflow；禁止形成双层工具栏侵占画布。
- 全屏与最大化不改变信息架构，只增加可见内容。

响应式使用重新定位、调整大小、重新排列、显示/隐藏和必要时重建；不得只把所有控件等比例缩小。官方参考：[响应式设计技术](https://learn.microsoft.com/zh-cn/windows/apps/design/layout/responsive-design)。

## 8. 输入模型

### 8.1 鼠标与触控板

- 单击选择；双击进入主编辑行为；右击打开 `MenuFlyout` 语义的上下文菜单。
- 滚轮默认垂直滚动；画布中滚轮缩放行为由设置决定，默认 `Ctrl+滚轮` 缩放。
- 中键拖动或 Space+左键拖动画布。
- 指针进入可拖动分隔条时改变光标并扩大实际命中区，不只依赖 1 px 视觉线。

### 8.2 键盘

- `Tab` 在主要交互元素之间前进；复合控件内部使用方向键。
- `Enter` 执行默认操作；`Space` 切换 Toggle/选择；`Escape` 从最内层状态逐次处理：取消 IME preedit → 结束文本编辑 → 取消当前手势 → 关闭 Flyout/Overlay → 返回上一层。每次按键只消费一个层级，已 commit 的文本继续由项目级 Undo 管理。
- 键盘焦点使用可见双层焦点框，不与选择框混淆。
- 快捷键不得在 `TextBox`、`PasswordBox`、`RichEditBox` 或 IME 组合输入期间劫持字符。

官方参考：[键盘交互](https://learn.microsoft.com/en-us/windows/apps/design/input/keyboard-interactions)。

### 8.3 触摸和笔

- 本阶段桌面鼠标键盘优先，但所有按钮至少保留 32 px 命中区；触摸优化模式下提升到 44 px。
- 画布支持双指缩放与平移；触笔用于选择和绘制 Region，触笔侧键等价右键。
- 触摸长按显示上下文菜单，但不能因轻微移动误触发。

## 9. 状态反馈选择

| 场景 | WinUI 3 参考控件 | 行为 |
| --- | --- | --- |
| 可计算、不中断的进度 | `ProgressBar` | 显示百分比或阶段进度 |
| 未知时长、局部阻塞 | `ProgressRing` | 仅阻塞所属区域，不冻结窗口 |
| 持久但非模态问题 | `InfoBar` | 占据布局空间，直到解决或关闭 |
| 新功能教学 | `TeachingTip` | 低频、可忽略，不用于错误 |
| 必须确认或不可继续 | `ContentDialog` | Smoke 遮罩，提供明确安全退出 |
| 上下文选项 | `Flyout` / `MenuFlyout` | 轻量消除，Escape 关闭 |
| 图标意义或快捷键 | `ToolTip` | 不包含交互控件 |
| 非侵入式待处理数量 | `InfoBadge` | 必须有出现和消失规则 |

短暂成功消息可由应用自定义 Toast 承担，但不能覆盖关键内容；持久错误必须进入页面内 `InfoBar` 或具体错误行。

## 10. 加载、空、错误与冲突

每个数据页面至少定义：

- `loading`：保留布局骨架，局部显示 `ProgressRing` 或 `ProgressBar`。
- `empty`：说明为何为空，提供一个直接下一步动作。
- `ready`：正常内容。
- `partial`：部分资源可用，例如项目可打开但源图移动。
- `error`：显示可操作原因、重试与诊断入口。
- `offline`：网络能力受限，但本地编辑仍可继续。
- `conflict`：后台结果与人工修改冲突，禁止静默覆盖。

同一错误不要同时弹 Toast、InfoBar 和 Dialog。选择最接近问题作用域的一种反馈。

## 11. 无障碍合同

- 所有交互元素暴露 Role、Name、Value、State 和必要的 Description。
- 图标按钮必须有可访问名称与 `ToolTip`；状态图标必须附带文本。
- 自定义画布需要独立的无障碍对象树：页面、Region、文本、状态和选择，而不是把整个画布暴露为一张不可读图片。
- 自定义复合控件定义稳定的 Tab Stop 与方向键导航；不可让每个内部装饰元素进入 Tab 顺序。
- 支持 200% 文本缩放；关键信息不得被固定高度裁切。
- Light、Dark、高对比度、透明效果关闭和减少动画均需单独验证。
- 焦点不得因异步内容刷新无故跳回页面顶部。

官方参考：[辅助功能概述](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-overview)、[可访问文本要求](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements)。

## 12. 文案原则

- 按钮使用动词开头：`新建项目`、`重试失败项`、`保存设置`。
- 进度文案说明对象和阶段：`第 19 页 · 正在翻译`，不只写 `处理中`。
- 错误文案三段式：发生了什么、影响什么、用户下一步做什么。
- 删除、覆盖、清空等危险行为在按钮上说明对象，不使用模糊的“确定”。
- AI 输出标注来源和不确定性；`翻译完成`表示流水线完成，不表示译文已经人工校对。
