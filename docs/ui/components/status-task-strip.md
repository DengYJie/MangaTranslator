# AppStatusTaskStrip 自定义控件设计

## 1. 控件定位

`AppStatusTaskStrip` 是整个应用窗口底部的持久状态区。WinUI 3 没有桌面工作台式 StatusBar 控件，因此该区域独立定义。它不承担关键错误提示，也不替代任务页面。

## 2. 区域结构

高度基准 32 px，从左到右：

1. Document Status：保存、Dirty、只读、保存失败。
2. Active Task：当前后台任务摘要。
3. Environment Status：设备、模型、网络等轻量状态。

每区之间用间距或细分隔线，不使用三个独立卡片。

## 3. 信息优先级

当空间不足时保留顺序：

1. 保存失败/未保存。
2. 可取消的运行任务。
3. 全局离线或模型不可用。
4. 自动保存说明。
5. GPU/内存等环境信息。

低优先级项进入一个状态 Flyout，由末端状态按钮打开。

## 4. Document Status

状态：

- Saved：勾号 + `所有更改已保存`。
- Dirty：圆点/编辑图标 + `有未保存更改`。
- Saving：活动指示 + `正在保存`。
- SaveFailed：Critical 图标 + `保存失败`，可点击打开 InfoBar 或详情 Flyout。
- ReadOnly：锁图标 + `只读`。

Saved 成功文案在 2–4 秒后可缩为图标或 `已保存`，避免长期占用；Dirty/Failed 持续显示。

## 5. Active Task

内容示例：

- `第 3 页 · 正在翻译 · 72%`。
- `批量任务 · 18/28 页`。
- `正在停止 OCR…`。

激活该区域返回任务所属页面。若有多个任务，显示最重要任务 + `另有 2 个任务`，点击打开 Flyout 列表。

可确定进度使用细 `ProgressBar`，可嵌入区域底边或 Flyout；未知进度使用活动图标。状态条本身不使用大 ProgressRing。

## 6. Environment Status

只展示与当前工作直接相关的状态：

- `GPU 可用` / `CPU 模式`。
- `离线`。
- `模型缺失`。
- 内存压力，仅超过阈值时。

普通情况下不要实时显示显存小数并持续跳动。详细诊断进入 Flyout。

## 7. 交互与动效

- 可点击区域 Hover 使用轻背景，100 ms。
- 状态文字变化使用 Cross-fade 120–160 ms，不横向滚动。
- Progress 更新不动画整个布局。
- SaveFailed、Offline 不闪烁。
- 任务完成时显示勾号 1–2 秒，再转为完成摘要；不抢焦点。

## 8. 响应式

- `>=1008`：三区完整显示。
- `720–1007`：Environment 缩为图标；Active Task 居中或占剩余空间。
- `<720`：只显示最高优先级状态和状态菜单按钮。
- 文本缩放导致 32 px 不足时允许高度增加到 40–48 px 或切紧凑文本，不能裁切。

## 9. 键盘与无障碍

- 整条状态栏不是一个 Tab Stop；仅可操作区域进入 Tab 顺序。
- 保存状态变化通过礼貌通知播报；频繁进度按里程碑播报。
- 图标有名称；状态文本不只靠颜色。
- 点击任务摘要的可访问名称包含动作：`打开批量任务，已完成 18/28 页`。

## 10. 验收清单

- 保存状态与任务状态同时变化时布局不跳动。
- 多任务可发现且可返回所属页面。
- 720 px 以下仍保留关键失败或任务信息。
- 状态条不覆盖页面内容，不与系统任务栏混淆。
- 高频进度不造成屏幕阅读器轰炸。
