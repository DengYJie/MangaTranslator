# 术语库 UI 设计

## 1. 页面目标

术语库用于维护一致译法，并让用户清楚区分全局术语、当前项目术语和翻译实际采用的有效术语。术语库始终可以从主导航进入，不以打开项目为前提。术语库在 V0.3 首次交付，重点是搜索、增删改查、来源追踪、覆盖关系、冲突发现和翻译注入状态。

WinUI 3 参考控件：`CommandBar`、`Button`、`AutoSuggestBox`、`ComboBox`、`TextBox`、`ToggleSwitch`、`InfoBar`、`InfoBadge`、`MenuFlyout`、`ContentDialog`、`ProgressRing`、`ToolTip`。

术语多列表格使用 MangaTranslator 自定义 [`GlossaryTableView`](../components/glossary-table-view.md)。它提供稳定列、排序、列宽调整、整行选择、键盘导航和表格无障碍语义；WinUI 3 本体没有可直接引用的第一方 DataGrid。

## 2. 上下文与术语视图

术语分为两种持久归属和一种派生视图：

- `全局术语`：独立于项目存在，可被所有项目复用。
- `当前项目`：随当前打开项目保存，只影响该项目。
- `有效术语`：全局术语与当前项目术语按规则合并后的只读结果，表示翻译请求实际采用的术语。

存在当前项目时，页面提供 `有效术语`、`当前项目`、`全局术语` 三个互斥视图，默认进入 `有效术语`。没有打开项目时只显示 `全局术语`，不显示禁用的 `有效术语` 或 `当前项目` Tab，也不阻止用户管理全局术语。

项目术语与启用的全局术语匹配同一规范化源词时，项目术语覆盖全局术语。有效术语行必须显示最终译法、真实来源以及 `覆盖全局`、`冲突`、`需要检查` 等状态。有效术语不是第三份持久数据，不能直接编辑；编辑动作必须定位到项目术语或全局术语的真实来源。

## 3. 页面结构

1. Page Header。
2. 项目上下文与术语视图切换。
3. 可选 `InfoBar`。
4. 主内容：术语列表 + 编辑 Pane。

### 3.1 Header

- H1：`术语库`。
- 说明：无项目时为 `管理所有项目可以复用的固定译法。`；有项目时为 `管理全局和当前项目使用的固定译法。`
- 命令：`导入`、`导出`、主按钮 `添加术语`。

`添加术语` 不打开模态 Dialog；在宽屏中清空并聚焦右侧编辑 Pane，在窄屏中打开全宽 Overlay 编辑 Pane。

### 3.2 项目上下文与视图切换

- 有项目时显示只读上下文 `当前项目：{项目名}`，长项目名截断并提供 ToolTip。
- 三个术语视图使用少量互斥视图的选择语义；切换视图保留各自的筛选、选择和滚动位置。
- 无项目时不显示空的项目上下文栏；可用轻量说明或 `InfoBar` 表达 `当前未打开项目，仅显示全局术语`，但不得表现为错误。
- 项目切换或关闭后立即重新计算可用视图；若编辑 Pane 有未保存修改，先按第 11 节处理，不能静默丢弃。

## 4. 术语列表

### 4.1 Toolbar

- 搜索：`AutoSuggestBox`，搜索原文、译文、别名和备注。
- 类型：`ComboBox`，全部、人名、地名、组织、技能、专有名词、自定义。
- 状态：全部、启用、禁用、冲突、需要检查。
- 结果数量。

顶层视图已经表达术语归属，不再重复提供 `全部 / 全局 / 当前项目` 作用域筛选。`有效术语`视图可增加 `全部来源 / 项目覆盖 / 仅全局` 的来源筛选，但它是结果筛选，不改变编辑归属。

输入搜索后 150–250 ms 防抖；本地过滤不显示 ProgressRing。远程或大索引查询超过 300 ms 时在搜索框结果区显示局部忙碌状态。

### 4.2 Column layout

Large 模式列：

- 原文。
- 固定译法。
- 类型。
- 来源；在持久视图中显示 `全局` 或当前项目名，在有效术语中显示最终采用来源。
- 状态。

列标题不可点击时只作为标签；支持排序后才显示可操作 Hover、焦点和排序箭头。

行高 52–60 px。原文与译文单行截断，完整内容通过 ToolTip；类型和来源为次级文本。冲突行显示 Caution 图标与 `冲突` 文本。

- 默认整行选择，不提供单元格内联编辑；编辑在右侧 Pane 完成。
- 原文和固定译法列优先获得剩余宽度；类型、来源和状态列使用受限宽度。
- 允许调整列宽并保存用户偏好，但关键列必须有最小宽度，不能被缩到不可理解。
- 列排序、键盘单元格导航、大数据流畅滚动和无障碍表格语义遵循 `GlossaryTableView` 控件规范。

### 4.3 Selection

- 在 `全局术语` 和 `当前项目` 中，单击选中并加载右侧编辑 Pane；双击聚焦第一个可编辑字段。
- 在 `有效术语` 中，单击显示只读解析详情；双击或 `编辑来源` 跳转到真实来源视图并聚焦对应条目。
- 持久视图支持 Ctrl/Shift 多选，用于批量启用、禁用、删除和移动归属；有效术语视图不提供破坏性批量编辑。
- 多选时右侧 Pane 切到批量摘要，不显示混乱的单项表单。

### 4.4 Row MenuFlyout

- 编辑；有效术语中显示为 `编辑来源`。
- 复制术语。
- 启用 / 禁用。
- 移到当前项目 / 移到全局；仅在存在当前项目且来源允许移动时显示。
- 查找使用位置。
- 删除；置于分隔符后。

有效术语只提供复制、编辑来源和查找使用位置，不直接提供启用、移动或删除。

## 5. 编辑 Pane

字段：

- 原文 `TextBox`，必填。
- 固定译法 `TextBox`，必填。
- 别名，可选多行 `TextBox`。
- 类型 `ComboBox`。
- 归属：全局 / 当前项目。无项目时固定为全局；有项目时使用 `RadioButtons` 或 `ComboBox`，并显示具体项目名。
- 备注与上下文，多行 `TextBox`。
- 在翻译请求中启用 `ToggleSwitch`。
- 大小写/全半角匹配策略；仅在对应语言适用时显示。

底部动作：

- 新增模式：`取消`、主按钮 `添加术语`。
- 编辑模式：危险 `删除`、主按钮 `保存更改`。
- 自动保存若未来启用，需要在字段旁明确状态；V0.3 使用显式保存，避免用户不确定修改何时生效。

有效术语的右侧 Pane 为只读解析详情，显示：最终采用译法、来源、是否覆盖全局、被覆盖条目以及匹配策略。主操作为 `编辑来源`，若同时存在项目与全局条目，可分别提供 `编辑项目术语` 和 `查看全局术语`。

## 6. 验证、覆盖与冲突

### 6.1 字段验证

- 原文为空：错误 `输入需要匹配的源术语`。
- 译文为空：允许保存为“禁止翻译”的特殊规则只有产品明确支持时才开放；V0.3 阻止保存。
- 同一持久归属内同原文重复：显示冲突列表，提供 `编辑现有术语` 或 `合并`。
- 全局和项目存在不同译法：允许，项目覆盖全局；标记为 `覆盖全局`，不把正常覆盖误报为错误。
- 同一归属内经过大小写、全半角和语言相关规范化后产生多个可用译法：标记为冲突，不能依赖列表顺序静默决定结果。

### 6.2 冲突解决

冲突行激活后编辑 Pane 顶部显示 `InfoBar`：

- 冲突来源。
- 当前翻译实际采用哪一项。
- 操作：保留项目覆盖、统一为当前译法、查看使用位置。

合并是可能破坏信息的操作，使用 `ContentDialog` 展示合并后结果和安全取消。

## 7. 导入与导出

### 7.1 导入

- Button 打开文件选择器。
- 导入目标默认为当前持久视图；从有效术语视图发起时必须先选择 `当前项目` 或 `全局术语`。无项目时只能导入全局术语。
- 解析完成后进入非模态预览页面或 `ContentDialog`；当冲突很多时应使用独立预览页，不把大表塞进 Dialog。
- 显示新增、更新、跳过、冲突数量。
- 用户选择覆盖策略后提交；失败项保留报告。

### 7.2 导出

- `SplitButton` 可用于主侧导出上次格式，菜单选择 CSV/TSV/JSON 等实际支持格式。
- 默认导出当前视图；导出有效术语时在文件元数据或来源列中保留解析后的来源，不把合并结果伪装成可重新导入的单一持久库。
- 无术语时禁用并显示原因 ToolTip。
- 成功后 Toast 提供 `打开文件夹`；失败使用页面内 InfoBar。

## 8. 页面状态

### 8.1 Empty

- 无项目且没有全局术语：显示 `添加第一个全局术语`、说明和主按钮。
- 当前项目没有项目术语：显示 `此项目还没有专用术语`，提供 `添加项目术语`；可说明仍会使用全局术语。
- 有效术语为空：说明当前项目没有可用的项目或全局术语，提供进入相应持久视图的动作。
- 过滤无结果：保留搜索工具栏，显示 `没有匹配项` 与 `清除筛选`，不显示首次使用插图。

### 8.2 Loading

- 初次载入超过 300 ms：列表中央 ProgressRing。
- 编辑 Pane 可显示占位，不能让旧术语内容短暂对应新选择。

### 8.3 Error

- 保存失败：编辑内容保留，字段上方 InfoBar 显示原因和重试。
- 索引失败：允许浏览已加载数据，搜索降级并说明。
- 有效术语解析失败：保留两个持久视图可编辑，在有效术语视图显示可重试的 `InfoBar`，不得继续使用无法解释来源的旧合并结果。

## 9. 响应式布局

### 9.1 `>=1200`

- 列表与 340–400 px 编辑 Pane 并列。
- 列表显示全部列。

### 9.2 `1008–1199`

- 编辑 Pane 340 px。
- 状态列可收为图标 + ToolTip，来源移入副标题。

### 9.3 `720–1007`

- 列表全宽。
- 编辑 Pane 作为右侧 Overlay；选中行不自动打开，Enter/双击或 `编辑` 命令打开。
- 工具栏筛选进入 Overflow，但搜索保持可见。

### 9.4 `<720`

- `GlossaryTableView` 切换为卡片呈现模式：原文 → 译文，第二行显示类型、来源、状态；信息模型、选择和可访问语义保持一致。
- 编辑 Pane 全屏覆盖内容区，有明确返回按钮，外壳 TitleBar 返回仍遵循路由历史，不与 Pane 内取消混淆。
- 术语视图切换保持可见；项目上下文可缩为带 ToolTip 的单行文本，不与视图切换合并成含糊下拉框。

## 10. 键盘与无障碍

- `Ctrl+F` 聚焦搜索。
- `Ctrl+N` 添加术语。
- `Ctrl+S` 保存当前编辑。
- Delete 对列表选择执行删除；必须避免在 TextBox 中拦截。
- 列表行可访问名称包含原文、译文、类型、来源和状态。
- 列标题与行单元格关联；窄模式仍提供完整语义。
- 冲突不能只用颜色或图标表达。
- 有效术语行的可访问名称必须包含最终译法、真实来源和覆盖/冲突状态。

## 11. 项目生命周期与未保存修改

- 从无项目状态打开项目：增加 `有效术语` 和 `当前项目` 视图，默认进入有效术语；保留全局视图的搜索与滚动状态。
- 切换项目：重新加载项目术语并重新计算有效术语，不沿用旧项目选择。
- 关闭项目：返回仅全局术语模式，不保留无效的当前项目筛选或编辑目标。
- 项目切换或关闭时存在 Dirty 编辑：提供 `保存并切换`、`放弃修改`、`取消`，不得静默保存到错误项目。
- 项目切换后，旧项目迟到的搜索或解析结果不得覆盖当前项目内容。

## 12. 验收场景

- 0、50、10,000 个术语的滚动和搜索。
- CJK、拉丁大小写、全半角、长备注和 Emoji。
- 全局与项目覆盖、重复、冲突合并。
- 无项目管理全局术语；打开、切换和关闭项目后视图与来源正确更新。
- 有效术语解析结果与翻译请求实际注入内容一致，且可追踪到真实来源。
- 保存失败后内容保留，切换选择前给出明确处理。
- 宽/窄布局、键盘多选、屏幕阅读器和高对比度。
