# V0.1 分段实施计划：人工辅助翻译闭环

> 状态：Planned  
> 依据：[技术决策](../technical-decisions.md)、[架构设计](../architecture-design.md)、[功能设计](../feature-design.md)、[产品路线图](../roadmap.md)

## 1. 目标与范围

V0.1 的目标是建立第一个可验收的纵向切片：

```text
创建或打开项目
→ 导入图片
→ 手工创建矩形 TextRegion
→ OCR 或人工录入原文
→ 翻译或人工录入译文
→ 纯色清除
→ 基础排版
→ Undo/Redo
→ 保存并重新打开
→ 导出 PNG/JPEG
```

### 交付范围

- JPG/JPEG、PNG、WEBP 和图片文件夹导入。
- 目录型项目：`project.json`、`assets/original/`、`assets/derived/`。
- UUID v4 的稳定 Page/Region ID。
- 源图像像素坐标下的轴对齐矩形 Region。
- 页面列表、漫画画布、Inspector 和基础命令区。
- 一个经过格式和许可证验证的 Manga OCR ONNX 实现，并保留人工录入。
- 一个非流式 OpenAI-compatible Chat Completions 适配器。
- 纯色/近似纯色清除层。
- 基础横排、竖排、换行、对齐、行距、边距和字号适配。
- 单页及批量 PNG/JPEG 导出。

### 明确不包含

CBZ/ZIP、PDF、自动文字检测、OpenCV/LaMa Inpaint、流式翻译、跨页上下文、完整术语工作流、Translation
Memory、旋转或多边形 Region、独立阅读顺序工具、WEBP 导出和完整日文禁则。

## 2. 阶段总览

```text
P0 工程基线
  ↓
P1 Domain 与项目格式
  ↓
P2 Application Port 与 UseCase
  ├──────────────┬──────────────┐
  ↓              ↓              ↓
P3 数据/导入     P4 服务/网络     P5 UI 与画布
  └──────────────┴──────────────┘
                 ↓
          P6 纵向切片集成
                 ↓
          P7 稳定性与验收
```

P3、P4、P5 在 P2 的公共接口稳定后可以并行。P6 前必须完成三条分支的契约测试和最小可运行实现。

## 3. P0：建立工程与构建基线

### 目标

建立可重复构建、可测试和可注入 Fake 的 CMake 工程。

### 工作项

- 创建 `CMakeLists.txt` 和 `CMakePresets.json`。
- 配置 C++23、Qt 6.11、vcpkg Manifest Mode 和 FluentQt CMake package。
- 建立 `manga_domain`、`manga_application`、`manga_data`、`manga_services`、`manga_network`、`manga_ui` 和应用目标。
- 配置 target-based include、compile features、链接和 `/W4`、`/permissive-`。
- 建立 `tests/unit/domain`、`tests/unit/application`、`tests/unit/ui`、`tests/contract` 和 `tests/integration` 的测试目标骨架。
- 为 Debug、Release、Test 配置 Qt/FluentQt 路径，不写死本机绝对路径。

### 退出条件

- 空应用可以启动并退出。
- Domain/Application 测试目标可以独立构建。
- 构建目录只产生在 `build/` 下。
- CI 或本地命令能复现配置、构建和 CTest。

## 4. P1：落地 Domain 与项目格式

### 目标

先固定用户数据模型，保证后续 UI、适配器和持久化不会各自定义格式。

### 工作项

- 实现 `ComicProject`、`ComicPage`、`TextRegion`、`TranslationEntry`、`TextLayout` 和图层模型。
- 实现 UUID v4、`ReadingDirection`、Region 几何边界和 2×2 最小尺寸规则。
- 实现 Region `orderIndex`，但不提供独立阅读顺序编辑器。
- 定义 JSON Schema Draft 2020-12。
- 定义 `projectVersion`、`schemaVersion`、`formatVersion`。
- 定义相对资产引用、源图和派生图层结构。
- 为项目配置保存 OCR、翻译、清除和排版默认值。
- 定义人工修改标记，确保异步结果不会覆盖人工文本、几何和排版。

### 测试

- 合法/非法 Region 几何和边界。
- 稳定 ID 序列化与反序列化。
- Schema 校验、未知版本拒绝和语义校验。
- 项目中页面顺序、Region、文本、排版和人工修改的往返一致性。

### 退出条件

- 不依赖 Qt Widget、数据库、网络或模型即可构造和比较领域对象。
- 一个最小项目可以序列化、反序列化并保留全部用户编辑数据。
- V0.1 格式字段已经冻结；后续变更必须走迁移设计。

## 5. P2：定义 Application Port 与 UseCase

### 目标

固定业务能力边界，使本地服务、网络适配器和 UI 可以独立替换。

### 工作项

- 定义 `IProjectRepository`、`IComicImporter`、`IOcrEngine`、`ITranslator`、`IInpainter`、`ITextLayouter` 和
  `IComicExporter`。
- 定义结构化错误、取消令牌、进度、请求 generation 和任务结果类型。
- 实现项目创建、打开、保存、导入、导出和关闭 UseCase。
- 实现 Region 创建、删除、移动、缩放、文本编辑和排版更新 UseCase。
- 实现 OCR、翻译、清除和排版的单页 UseCase。
- 定义按 Region ID 合并翻译结果的协议校验。
- 定义异步结果提交前的项目、页面、generation 和人工修改检查。

### 测试

- UseCase 成功、输入校验、空输入、Port 失败、取消和过期结果。
- 翻译响应缺失、重复和未知 Region ID。
- 人工版本优先和不可覆盖规则。
- Fake Port 不启动 GUI、不访问网络或真实凭据。

### 退出条件

- UseCase 不依赖 QWidget、QGraphicsItem、FluentQt、HTTP、ONNX 或具体数据库实现。
- 所有长操作都有明确的取消、进度和错误结果。
- P3、P4、P5 可以只依赖已冻结的接口和数据类型开发。

## 6. P3：实现数据层与图片导入

### 目标

完成可恢复的目录型项目和 V0.1 图片来源导入。

### 工作项

- 实现项目目录创建、打开、保存、另存和恢复检查。
- 使用临时文件写入 `project.json`，成功后原子替换并保留 `.bak`。
- 默认将源图复制到 `assets/original/`，只保存项目内相对路径。
- 将可重建清除层、译文层和缩略图放入 `assets/derived/`。
- 导入图片文件和文件夹，支持 JPG/JPEG、PNG、WEBP。
- 实现 Unicode NFKC 后的稳定自然排序。
- 导入时应用 EXIF 方向，生成 RGBA8、straight alpha、sRGB 工作图。
- 处理源文件读取失败、重复文件名、Unicode 路径和磁盘空间错误。

### 测试

- Unicode 路径和自然排序。
- 损坏图片、缺失源文件和重复名称。
- 保存中断、临时文件、备份恢复和原子替换。
- 高位深/ICC/EXIF 输入转换。

### 退出条件

- 创建、保存、关闭、重新打开项目后数据一致。
- 保存失败不破坏原项目。
- 源图永不被写入或覆盖。

## 7. P4：实现 OCR、翻译、清除与排版服务

### 目标

提供 V0.1 的最小可用处理能力，并隐藏第三方实现细节。

### 工作项

- 实现 Manga OCR ONNX 适配器；固定模型 Manifest、输入输出、许可证和模型缺失错误。
- 使用有界 `QThreadPool + QRunnable` 执行 OCR、翻译、清除和排版任务。
- 实现 Windows Credential Manager 凭据读写，不将密钥放入项目、QSettings 或日志。
- 实现 OpenAI-compatible 非流式 Chat Completions 适配器。
- 固定单页 Region 请求和结构化响应 Schema。
- 实现超时、有限重试、限流错误、取消和安全诊断。
- 实现纯色/近似纯色清除，输出独立清除层。
- 使用 Qt 文本布局实现横排、竖排、换行、对齐、行距、边距和字号二分适配。
- 对缺失字体、缺失字形和溢出提供结构化状态。

### 测试

- OCR 模型缺失、模型错误、输入错误和取消。
- 翻译协议异常、超时、限流和取消后的迟到响应。
- 不记录完整漫画文本、密钥或完整远程响应。
- 纯色清除成功、无效区域和失败保留原图。
- 横排/竖排布局、溢出和字体回退。

### 退出条件

- 第三方类型不穿过 Application Port。
- 处理期间 GUI 线程保持可响应。
- 所有结果带有项目、页面和请求身份，过期结果被拒绝。

## 8. P5：实现 UI、MVVM 与漫画画布

### 目标

建立能够完成 V0.1 主线的可用桌面界面。

### 工作项

- 按 `BaseViewModel`、State、`updateState`、`stateChanged`、`observe` 实现屏幕状态流。
- 实现应用外壳、首页/项目中心、新建项目/导入、编辑器和设置入口。
- 编辑器使用页面缩略图、`QGraphicsView/QGraphicsScene` 画布和 Inspector。
- 实现手工创建、选择、移动、缩放和删除矩形 Region。
- 实现原文、译文、字体、字号、方向、对齐、行距和边距编辑。
- 实现原图、清除、翻译和对比预览；V0.1 对比采用并排模式。
- 实现 Command Bar 的 Undo/Redo、OCR、翻译、清除、排版和导出意图。
- 实现拖动合并、连续文本输入合并和异步结果显式采用。
- 使用 FluentQt 公共 API 和语义主题 Token，不添加全局 QSS 或自定义 QStyle。
- 覆盖 Light/Dark、窄宽度、空状态、错误、取消、加载和字体缺失状态。

### 测试

- ViewModel 初始 `observe`、无变化更新抑制和预期 State 序列。
- 过期异步结果、View 销毁和取消。
- 画布坐标往返、缩放独立命中、选择身份和命令 Undo/Redo。
- 键盘焦点、IME、Tooltip、Escape/取消和可访问名称。

### 退出条件

- View 不直接访问 Repository、网络客户端或推理服务。
- `QGraphicsItem` 只投影 State，不保存权威领域数据。
- 窄窗口仍可访问页面、画布、Inspector 和主要操作。

## 9. P6：完成纵向切片集成

### 目标

把 P3、P4、P5 连接成一个真实可操作的单页工作流。

### 工作项

- 由 `ApplicationContext` 构造 Repository、Provider、Service、UseCase、ViewModel 和窗口。
- 按启动顺序初始化 DPI、Qt、FluentQt 资源、字体、设置、日志和主题。
- 打通“创建/打开 → 导入 → 创建 Region → OCR/人工录入 → 翻译/人工录入 → 清除 → 排版”。
- 打通项目保存、重新打开、当前页面恢复和导出。
- 实现单页及选定页面的批量图片导出。
- 实现底部状态/任务反馈、可恢复错误和一次性 Toast/InfoBar 事件。
- 验证关闭页面、项目和应用时取消或隔离后台任务。

### 退出条件

- 使用真实本地图片完成完整主线，不依赖自动文字检测。
- 重新打开后页面、Region、原文、译文、排版和人工修改一致。
- 导出失败不会留下被误认为成功的半成品。

## 10. P7：稳定性、质量与发布验收

### 目标

确认 V0.1 具备进入 V0.2 的基础，而不是只完成演示路径。

### 工作项

- 运行 Domain、Application、UI、契约和集成测试。
- 检查源图不可变、项目保存恢复和异步过期结果隔离。
- 使用确定性测试数据验证单页与批量导出。
- 在 Light/Dark、正常/窄宽度、高 DPI 下检查关键页面和状态。
- 检查 API 凭据、日志、项目文件和诊断信息的隐私边界。
- 生成 V0.1 已知限制清单，明确 V0.2 接口预留但不提前实现。

### V0.1 通过门槛

- 主线可以稳定完成并重新打开。
- 所有人工编辑可撤销，保存不会清空 Undo 历史。
- OCR、翻译、清除、排版和导出失败都有可见且可恢复的状态。
- 后台任务不会阻塞 GUI，也不会覆盖新项目或人工修改。
- PNG/JPEG 导出成功，文件冲突不覆盖已有文件。
- 未引入 CBZ/PDF、自动检测、复杂 Inpaint、流式翻译或 V0.3 能力。

## 11. 推荐执行顺序

1. 先完成 P0 和 P1，冻结工程依赖和项目数据格式。
2. 完成 P2，冻结 Port、错误、取消和请求身份协议。
3. 并行推进 P3、P4、P5；每条分支使用 Fake 或最小适配器保持可测试。
4. 以 P6 的单页纵向切片为集成主线，不先实现批处理或自动检测。
5. P7 通过后再启动 V0.2，不在 V0.1 中提前引入 CBZ/PDF、OpenCV 或检测模型。
