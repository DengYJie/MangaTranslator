# MangaTranslator V0.3 技术决策

> 状态：V0.3 基线已锁定  
> 适用范围：V0.3 整章智能工作流  
> 前置基线：[V0.1 技术决策](technical-decisions.md)、[V0.2 技术决策](v0.2-technical-decisions.md)  
> 关联文档：[架构设计](architecture-design.md)、[功能设计](feature-design.md)、[产品路线图](roadmap.md)

## 1. 交付边界

V0.3 在 V0.2 的页面流水线上增加可恢复的整章任务、受控的跨页上下文、完整术语工作流、Translation Memory、规则式阅读顺序候选、LaMa 漫画清除、进阶排版和集中校对。

V0.3 明确不包含：

- DirectML、CUDA 或其他 GPU 推理后端；ONNX Runtime 只交付 CPU。
- 流式翻译、云端后台任务和应用退出后的继续处理。
- Region 旋转、多边形 Region、完整振假名、任意路径文字和复杂拟声词艺术字。
- 无人校对的一键发布、后台结果覆盖人工内容，以及模型自动将页面标为已校对。

## 2. 项目数据与任务存储

### 2.1 目录结构

```text
ProjectName/
├── project.json
├── project.db
└── assets/
    ├── original/
    └── derived/
```

- `project.json` 保存项目内容、页面、Region、项目术语、排版和当前处理配置。
- `project.db` 保存 `BatchJob`、页面阶段状态、任务事件、重试与恢复信息，以及项目级 Translation Memory。
- 大图、Mask 和处理输出保存在 `assets/derived/`；数据库只保存相对资产引用、内容摘要和结果版本。
- `project.json` 仍是用户编辑内容的权威数据；任务数据库不能成为页面、Region、原文、译文或人工排版的唯一副本。

### 2.2 SQLite 基线

- `project.db` 使用 SQLite WAL、外键约束和事务。
- SQLite 版本通过 vcpkg baseline 固定，运行时版本不得低于 `3.51.3`；不得使用受 WAL-reset 缺陷影响的版本。
- 打开数据库后必须确认 `PRAGMA journal_mode=WAL` 实际成功，不能只发出命令后假定已启用。
- 使用一个串行化写入通道维护任务状态顺序；只读查询可以使用独立连接。写入方仍需处理 `SQLITE_BUSY`，不能假定 WAL 支持多个并发 Writer。
- 以崩溃恢复为优先，V0.3 使用 `synchronous=FULL`。Checkpoint 由数据库组件统一管理，不能由各任务线程各自触发。
- 可写项目必须位于本机文件系统。网络文件系统不支持 SQLite WAL 的共享内存语义；此类项目提示复制到本地后编辑，不以可写模式打开。
- `project.db-wal` 和 `project.db-shm` 是活动数据库状态的一部分，不得在数据库打开时单独复制、删除、移动或替换。

活动数据库的备份使用 SQLite Online Backup API，不能直接复制主数据库文件。完整项目快照需要先阻止新的项目写入、提交当前 `project.json`、通过 Backup API 复制数据库，再将 JSON、数据库快照和所引用资产作为同一快照发布。SQLite 事务不能让 `project.json` 与 `project.db` 跨文件原子提交，因此备份清单必须记录两者对应的项目修订。

### 2.3 任务身份与快照

每个阶段请求至少携带：

```text
projectId + jobId + pageId + stage + requestGeneration
```

任务还保存不可变输入快照摘要、配置快照、模型/Provider 版本、依赖阶段结果版本、开始与结束时间、重试次数和最后错误。提交结果前必须重新验证项目仍打开、请求 generation 未过期、输入版本未变化，且人工内容未获得更高优先级。

## 3. 整章任务状态机

### 3.1 状态

```text
pending -> running -> succeeded
   |          |  \-> failed
   |          |  \-> cancelled
   |          |  \-> interrupted
   |          \----> stale
   \--------------> blocked
```

状态含义：

| 状态 | 含义 |
| --- | --- |
| `pending` | 输入已准备，等待调度 |
| `running` | 当前阶段正在执行 |
| `succeeded` | 当前输入和配置下已产生有效结果 |
| `failed` | 阶段运行失败，可按错误策略重试 |
| `cancelled` | 用户取消，迟到结果必须拒绝 |
| `interrupted` | 进程或项目在运行中断开，结果完整性未知 |
| `stale` | 上游输入、配置或采用结果已变化，旧结果不可作为当前结果 |
| `blocked` | 缺少必需输入、预算或可恢复条件，用户处理前不调度 |

### 3.2 调度与恢复

- 暂停只阻止新阶段启动；已运行且能安全完成的阶段不被强杀。UI 显示仍在收尾的任务。
- 取消停止等待并使 generation 失效；即使底层调用无法立即中止，返回结果也不得发布。
- 应用启动后将遗留的 `running` 原子转为 `interrupted`，不能把它们推断为成功。
- 恢复只重新调度 `interrupted`、`failed` 和用户明确选择的 `stale`。
- 重试从失败阶段开始；输入和配置未变化的成功上游阶段不重复执行。
- 上游输入、采用结果或有效配置改变时，下游阶段按依赖图标记 `stale`。
- 关闭项目先暂停并持久化任务，不再向该项目的 State 或模型发布结果。
- 关闭应用会停止本地调度；V0.3 不继续后台处理。
- 页面某阶段失败不抹除其他页面或其他已成功阶段。

所有状态转换与相应事件记录在同一事务中。任务恢复逻辑以当前状态和版本为依据，不能通过日志文本猜测状态。

## 4. 上下文翻译

### 4.1 请求与上下文范围

翻译提交和输出单位仍是一页。上下文只帮助翻译当前页，不允许响应返回或修改前页数据。

默认上下文：

- 当前页：全部 Region 原文，按当前已保存 `orderIndex` 排列。
- 前文：最多前 2 页的人工确认文本。
- 章节摘要：最多 1,000 token。
- 术语：全部命中的强制项目/全局有效术语，以及用户为本次任务明确指定的术语。
- TM：每个 Region 最多 5 个候选。

先预留最大输出 token 和安全余量，再计算可用输入预算。输入预算的目标分配为：

| 内容 | 预算 |
| --- | ---: |
| 当前页和强制术语 | 至少 70% |
| 前页、章节摘要和 TM 上下文 | 最多 20% |
| 协议、结构与系统开销 | 预留 10% |

当前页 Region、命中的强制术语和用户明确指定的术语不得裁剪。超限时按以下顺序裁剪：

1. 低分 TM 候选；
2. 较早页面原文；
3. 章节摘要；
4. 仍然超限则进入 `blocked`，要求用户缩小任务或更换上下文容量更大的模型。

Provider 提供兼容 tokenizer 时使用精确计数；否则使用保守估算并保留安全余量。服务端报告实际用量时记录诊断数据，但不得记录密钥或默认记录完整漫画文本。

“上下文失败后转为纯单页翻译”是任务配置项，默认关闭。启用并发生降级时，结果必须带有可见的“已降级为单页翻译”状态，不能静默处理。

### 4.2 缓存与响应验证

缓存键至少包含：

- Provider 配置身份、模型和非敏感请求参数；
- `promptVersion` 与 `responseSchemaVersion`；
- 源语言、目标语言和阅读方向；
- 有序的 `(regionId, normalizedSourceText)`；
- 有效术语 Hash、TM 候选 Hash、上下文页及版本和章节摘要 Hash；
- 温度、最大输出等会改变结果的生成选项。

密钥和完整 endpoint 凭据不进入缓存键或日志。响应继续按 Region ID 验证：重复 ID 使整次响应失败，未知 ID 被忽略并记录安全诊断，缺失 ID 使相应 Region 失败。不得按数组位置匹配。

## 5. 术语库

### 5.1 数据归属与覆盖

- 全局术语保存在用户数据目录 SQLite；项目术语保存在 `project.json`。
- 项目术语覆盖相同规范化键的全局术语，有效术语保留最终来源。
- 修改术语后重新解析当前项目；已有译文不得自动重写，只标记 `needsReview`。
- 全局术语修改不能静默改变历史译文。
- 停用保留历史和引用，但不注入翻译。存在引用的条目不能物理删除，只能停用；无引用条目才允许删除。

### 5.2 V0.3 能力

- 类别：`person`、`place`、`organization`、`skill`、`title`、`item`、`properNoun`、`custom`。
- 匹配模式：`exact` 与 `wholeWord`；不支持正则表达式。
- `wholeWord` 对有显式词边界的文字按 Unicode 词边界匹配；CJK 不假定空格分词，按规范化字面序列匹配，并将重叠命中显示为冲突供用户确认。
- 大小写不敏感，规范化使用 Unicode NFKC、去首尾空白和大小写折叠。
- 别名保存为独立条目，并用 `termGroupId` 关联到同一概念。
- `ruleType` 区分普通翻译与 `doNotTranslate`；禁止用空目标文本隐式表达禁止翻译。

规范 CSV 列为：

```text
sourceLanguage,targetLanguage,source,target,category,termGroupId,matchMode,ruleType,isEnabled,note
```

兼容导入器可以接受 `aliases` 便捷列，但必须展开为共享 `termGroupId` 的独立条目；规范导出始终一行一个条目。导入冲突逐项报告，用户可以跳过、覆盖或保留两者。批量导入不得无提示覆盖现有条目。

## 6. Translation Memory

### 6.1 存储与写入

- 项目 TM 保存在 `project.db`，全局 TM 保存在用户数据目录 SQLite；TM 与术语库是独立数据集。
- 项目 TM 可以自动记录人工确认或用户明确采用的结果。
- 只有人工确认或用户明确采用的译文可以进入全局 TM。
- 未经确认的模型译文不能自动进入全局 TM。
- TM 只保存源文、译文、语言、来源、确认信息和有限上下文摘要，不保存页面图像。
- 修改或删除 TM 不改变已经保存的页面译文。

### 6.2 匹配

规范化顺序为：

```text
Unicode NFKC
-> 去首尾空白
-> 连续空白折叠
-> 大小写折叠
```

NFKC 已包含常见全角/半角兼容归一化，不再增加第二套宽度转换。精确键为：

```text
sourceLanguage + targetLanguage + normalizedSourceText
```

上下文只作为候选排序指纹，不是精确命中的必要条件。

- 默认只展示建议；启用“自动采用精确 TM”后，精确命中才可自动采用。
- 模糊匹配使用归一化 Levenshtein，相似度阈值初始为 `0.85`，最多返回 5 条。
- 少于 4 个 Unicode code point 的文本不做模糊匹配，避免短文本误命中。
- 模糊结果永远不能自动采用或覆盖人工译文。
- `0.85` 是待样本验证的产品初值，不是通用行业标准。

## 7. LaMa 漫画清除

### 7.1 固定候选与真实接口

V0.3 技术候选为 `mayocream/lama-manga-onnx` 的 `lama-manga.onnx`：

| 项目 | 固定值 |
| --- | --- |
| 文件修订 | `d306b6b639576677fef3239261a4a145c21efecf` |
| 文件大小 | `207,482,644` bytes |
| SHA-256 | `4512adab295ee5a5e02ccd1bdf8d45dccbac88309d9cff1532ffd5de876f02a4` |
| 执行后端 | ONNX Runtime CPU |
| `image` 输入 | `float32 [batch, 3, 512, 512]` |
| `mask` 输入 | `float32 [batch, 1, 512, 512]` |
| `output` | `float32 [batch, 3, 512, 512]` |

该 ONNX 的实际接口是独立 `image` 与 `mask` 输入，不是单个四通道张量。RGB 数值范围、Mask 极性和输出裁剪必须由固定金样测试确认后写入模型 Manifest，不能仅从通用 LaMa 实现推断。

Hugging Face 页面标注 Apache-2.0，关联模型卡标注 MIT，但仓库页面的许可证元数据不能单独证明源权重、训练数据和 ONNX 转换物的完整再分发权利。发布前必须分别核验原始 LaMa 代码、源 checkpoint 和具体 ONNX 文件；审核未通过时只能作为用户自行下载的实验模型，不能随应用分发。

### 7.2 MangaTranslator 处理策略

- 模型 Manifest 固定模型 ID、修订、文件名、大小、SHA-256、接口、许可证状态和兼容后端。
- 以 Mask 包围盒和上下文边距裁剪处理区域；不足 512 px 时 padding，不能越过源页面。
- 大区域使用 512×512 推理块，默认重叠 64 px，并在重叠区平滑融合。
- Mask 默认扩张 2 个源图像像素；扩张值属于可版本化处理配置。
- 64 px 重叠、融合、裁剪和 2 px 扩张是应用策略，不是模型能力声明，必须通过接缝、细线和页面边缘金样测试。
- V0.3 只交付 CPU；DirectML 和 CUDA 不作为隐藏或实验发布能力。

结果与回退：

```text
LaMa 成功 -> 生成独立候选清除层
LaMa 失败 -> 保留现有 OpenCV 结果并产生 Error/Caution 问题
LaMa 不可用 -> 不改变已有 OpenCV 或人工清除层
```

后台结果永远是候选。只有用户明确采用后，才以一个复合 Undo 命令替换当前清除层引用；人工清除层优先，迟到结果不得覆盖。

## 8. 自动阅读顺序

V0.3 使用确定性几何规则生成候选，不引入独立阅读顺序模型。

1. 根据垂直或水平重叠将 Region 聚类为行或列。
2. 横排项目主要按 Y 分组，竖排项目主要按 X 分组。
3. 左到右时组内 X 升序；右到左时组内 X 降序。
4. 组之间按项目阅读方向排序。
5. 无法确定时保留当前 `orderIndex`，生成低置信候选并标记 `Caution`。

混合横竖排页面不强行推断唯一全局顺序。当前保存的 `orderIndex` 始终是翻译和导出的权威顺序；自动排序只产生候选，用户采用后以一个复合 Undo 命令写入。新 Region 默认插入最近几何位置之后；删除只重排显示序号，不改变其他 Region ID。批量翻译不得使用尚未采用的候选顺序。

## 9. 高级排版

V0.3 承诺：

- 基础日文行首/行尾禁则与竖排标点方向。
- 中英文混排、字体回退和缺字提示。
- 字号、行距和边距联合适配。
- 项目级排版预设与多 Region 批量应用样式。
- 明确的溢出原因、影响范围和修复入口。

自动适配优先级固定为：

```text
减少字号 -> 调整行距 -> 缩小边距 -> 报告溢出
```

不得为适配空间自动改写、删减或概括用户译文。V0.3 不承诺完整振假名、任意路径文字、复杂拟声词艺术字、全部 OpenType 竖排特性或气泡形状最优排版。

## 10. 集中校对与问题严重级别

| 级别 | 行为 |
| --- | --- |
| `Info` | 提供信息，不要求处理 |
| `Caution` | 建议检查，不阻止完成或导出 |
| `Error` | 默认阻止；用户可以明确忽略并留下审计记录 |
| `Blocking` | 数据或协议无法形成有效输出，不允许忽略，必须解决 |

`Blocking` 包括：

- 未被 `doNotTranslate` 或“有意留空”确认豁免的空译文。
- Mask 缺失、坐标非法或页面资源无法读取。
- 启用清除时清除阶段失败且没有已采用的有效清除层。
- 翻译响应出现重复 Region ID，或必需 Region ID 缺失且没有人工译文。

`Error` 包括：

- 字体缺字、当前结果 stale、术语冲突或 TM 候选冲突。
- 译文溢出且用户尚未明确接受该结果。
- 上下文翻译失败且没有成功的显式降级结果。
- OpenCV/LaMa 质量回退需要人工确认。

OCR 低置信度、成功但明确标记的单页降级和低置信阅读顺序候选属于 `Caution`。如果问题允许用户忽略，它就不能标为 `Blocking`。

忽略 `Error` 时保存：

```text
issueCode
severity
ignoredByUser
ignoredAt
optionalReason
inputVersion
```

输入变化后旧忽略记录不自动适用于新问题版本。“已校对”只能由用户确认，不能由模型评分、流水线成功或无可见问题自动设置。

## 11. V0.2 到 V0.3 迁移

- 提升 `project.json` 的 `schemaVersion` 和整体 `formatVersion`，并在 `project.db` 内维护独立 `databaseSchemaVersion`。
- 创建 `project.db`，把 V0.2 处理配置复制为版本化配置快照；任务、TM 和索引表按需创建。
- 页面和 Region ID 原样保留。
- 迁移前生成完整 `.bak` 快照；数据库部分使用 SQLite Backup API。
- 迁移写入暂存位置并完成校验后再发布。失败时保留原项目，不能留下被 V0.2 或 V0.3 误判为完整的新格式。
- 大型派生缓存允许丢弃并重建；页面、Region、用户文本、译文、项目术语和人工修改不得丢失。
- 未加入前向兼容逻辑的 V0.2 应用必须拒绝编辑 V0.3 项目并清楚提示版本过新。只有发布过专门兼容更新的 V0.2 Reader 才能只读打开；不能假设旧二进制天然理解新格式。

迁移测试必须覆盖成功、磁盘空间不足、进程中断、数据库损坏、备份恢复、未知新版本和重复迁移。

## 12. 测试门槛

- 状态机合法转换、事务一致性、应用崩溃后的 `interrupted` 恢复、局部重试和 stale 传播。
- WAL 启用失败、Busy Writer、Checkpoint、Backup API、网络路径拒绝和固定安全 SQLite 版本。
- 上下文预算、裁剪顺序、不可裁剪内容、blocked、显式单页降级和 Region ID 协议错误。
- 术语覆盖、CJK 匹配、别名组、禁止翻译、停用/引用和 CSV 冲突导入。
- TM 写入资格、NFKC、精确/模糊命中、短文本和人工版本优先。
- 固定 LaMa 文件 Hash、真实输入输出元数据、Mask 金样、切块接缝、页面边缘、失败回退和复合 Undo。
- 阅读顺序候选、混合排版、人工采用和权威 `orderIndex`。
